Evidence over hype · AI for geoscience

Does the AI actually do the science — and at what cost?

FrugalMind is an open evaluation framework for scientific AI agents in the geosciences. It measures whether a model or multi-agent system meets a task-specific quality floor, and what it costs to get there — so labs can adopt AI on the strength of measured evidence, not demos and anecdotes.

Why this exists

Geoscience needs proof, not vibes.

AI is arriving in seismology, geodesy, and Earth science faster than our ability to check it. A model that writes fluent code can still fetch the wrong station, hallucinate an earthquake in a quiet window, or round a magnitude away. Frontier models are also expensive, and most labs cannot spend a premium on every step of a workflow. FrugalMind answers two questions at once:

◎

Is it right?

Scored against reference truth with a numeric tolerance wherever possible — not a vibe check. Negative cases (a window with no event) are first-class, so we catch confident hallucination, not just missed detections.

$

What did it cost?

Every row carries token cost in dollars. The interesting winner is not the highest score — it is the cheapest system that still clears the quality floor.

◇

Is it reproducible?

Pinned sandboxes, deterministic scorers, and a parametric truth set mean a score means the same thing next month. Hidden test splits keep the numbers honest.

The task suite

Three families, because geoscience work is diverse.

Real research is not one kind of task. A useful benchmark has to cover reading and reasoning over the literature, running real pipelines, and coordinating multi-step workflows. Each family is scored differently, by the most verifiable method the task allows.

1

Literature & multimodal

Review, critique, translation, interpolation, and retrieval-augmented QA over papers, figures, and waveforms.

Scored by: retrieval metrics (recall@k, nDCG), domain-term preservation, and citation grounding — no fabricated sources.

Design doc →
2

Coding agents

Prompt → code (run it, check the artifact) and prompt → data (drive a real pipeline — seisbench, noisepy, codameter — and check the numbers).

Scored by: sandboxed execution and numerical regression against a reference within tolerance.

Design doc →
3

Orchestration

Non-linear workflows where an agent decides which sub-agents to call, in what order, with what dependencies — a plan graph, not a straight line.

Scored by: the sub-agent call DAG vs a reference — right steps, right dependencies, and frugal fan-out.

Easy → hard

We grade by how verifiable the answer is.

The hardest part of evaluating open-ended science is trusting the score. FrugalMind pushes every task as far up this ladder as it will go — toward a deterministic reference — and only falls back to a judged rubric when nothing else fits. Higher tiers are cheaper to score and harder to game.

  1. T0Deterministicexact value + tolerance (FDSN query fields)
  2. T1Numericalarray vs reference (pick times, CCF)
  3. T2Perceptualfigure vs golden (SSIM)
  4. T3Trajectorycall DAG vs reference plan
  5. T4RubricLLM-judge, only as fallback

Difficulty also comes from the data. Items carry a public validation split and a hidden test split, a cutoff_date that bars a model from using information it could not have had at the time, and negative cases an over-eager model will fail.

Skills

A good skill can lift a small model to frontier quality.

The same task can be presented three ways: with none of a domain skill, with its instructions, or with the full skill loaded. Measuring the gap — the skill lift — shows how much a cheap, open, local model gains from domain guidance. Often a small model plus a skill clears the same quality floor as a frontier model at a fraction of the cost. That is the whole frugality thesis, made measurable. Transparency

Fair comparison is a labeled comparison.

A score with no context invites hype. Every leaderboard row states the model's openness (open weights vs API-only), its toolset (standard vs custom scaffolding), the exact suite, the cost, and how many items it actually completed. An open 7B model with standard tools is never silently compared against a closed model with a custom harness. Published like this, adoption decisions rest on evidence a reviewer can reproduce — not a screenshot from a launch post.

LIVE RUN — real inference. Four open 7–8B models running locally under Ollama (qwen2.5, llama3.1, deepseek-r1, olmo2) plus claude-haiku via the Anthropic API, over two evals: dv/v processing (codameter) and STA/LTA detection (Ridgecrest synthetic). Real prompts, real skill injection, code executed in the sandbox, graded by the deterministic scorers. Costs are actual token usage — local open-weight models bill $0 marginal.

What it shows: whether you can be frugal depends on the task. On dv/v parameter choice, free local models (qwen2.5:7b, llama3.1:8b) reach a perfect 1.00 with the domain skill — matching claude-haiku at zero cost. On STA/LTA code generation, every 7B model fails (~0.10): they import the right ObsPy functions, then hand-roll a buggy detector that crashes. Only the cloud model writes working code (0.56 → 0.76 with the declustering skill). Skills rescue a small model on config tasks; they do not rescue one that cannot write correct numerical code.
